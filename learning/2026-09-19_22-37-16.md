## 1. Database Architecture & Schema Optimization

### `SERIAL` vs. `BIGSERIAL` (Integer Overflow Mechanics)
- **`SERIAL` (4-byte Integer):**
  - Range: $-2,147,483,648$ to $+2,147,483,647$ (~$2.14$ billion).
  - Risk: Starting an auto-increment counter at $1,000,000,000$ leaves only ~$1.14$ billion available IDs before an integer overflow exception occurs.
- **`BIGSERIAL` (8-byte Integer):**
  - Range: Up to $+9,223,372,036,854,775,807$ (~$9$ quintillion).
  - Prevents sequence exhaustion while starting at large integer offsets.

## 2. PostgreSQL Sequences Under the Hood
- **Sequence Generator:** A stateful counter machine decoupled from the table data itself.
- **Default Naming Convention:** Automatically created as `<table_name>_<column_name>_seq` (e.g. `link_table_id_seq`).
- **Offset Modification:**
  ```sql
  ALTER SEQUENCE link_table_id_seq RESTART WITH 1000000000;
  ```
  - Repositions the sequence pointer so the subsequent `nextval()` call outputs $1,000,000,000$.
  - Generates Base62 strings of predictable length (e.g., 6 characters) on day one without collision risk.

---

## 3. Automatic Indexing via Constraints
- When a column is defined with the **`UNIQUE`** or **`PRIMARY KEY`** constraint, PostgreSQL automatically provisions an underlying B-Tree index.
- A redundant `CREATE INDEX` statement on that column is unnecessary and wastes write overhead.

---

## 4. Timestamps & Timezones
- **`TIMESTAMPTZ`:** Stores timestamp converted to UTC internally, translating to local timezone upon display.
- **`DEFAULT CURRENT_TIMESTAMP`:** Offloads timestamp generation entirely to the database engine, avoiding clock-skew discrepancies between client application instances.
