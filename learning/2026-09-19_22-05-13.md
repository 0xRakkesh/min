## 1. Python Scope & Variable Mutability
- **Module Scope vs. Local Function Scope:**
  - Reading an external variable inside a function is permitted by default.
  - Reassigning an external variable using operators like `+=` causes Python to treat it as a new local variable, triggering `UnboundLocalError: local variable referenced before assignment`.
  - The `global` keyword (`global counter`) explicitly instructs Python to modify the module-level variable rather than initializing a local one.

## 2. FastAPI Request Body Mechanics
- **Function Parameter Binding:**
  - Declaring a Pydantic model in the endpoint signature (`def root(url_data: URLitems):`) informs FastAPI to parse, validate, and bind the incoming JSON body.
  - An empty parameter list (`def root():`) leaves FastAPI unaware of any expected request body.
- **Instance vs. Class Access:**
  - `URLitems.target_url` references the class definition/type descriptor.
  - `url_data.target_url` accesses the actual validated string for that specific incoming request.

## 3. Data Structure Performance: Hash Table vs. Array
- **List / Array (`[]`):**
  - Requires a linear scan from index 0 to $N-1$.
  - Time Complexity: **$O(N)$**. At 100 million entries, lookup latency degrades catastrophically.
- **Dictionary / HashMap (`{}`):**
  - Evaluates the key through a hash function to jump directly to memory buckets.
  - Time Complexity: **$O(1)$**. Instant lookup regardless of whether there are 10 items or 100 million items.

## 4. HTTP Redirection: Absolute vs. Relative Paths
- **Absolute URLs:** Must include the protocol scheme (e.g., `https://` or `http://`). Informs the client browser to exit the current origin and navigate to the external domain.
- **Relative URLs:** If the protocol scheme is omitted (e.g., `example.com`), the browser treats it as a subpath on the local host origin (`http://127.0.0.1:8000/example.com`).
- **HTTP 307 (Temporary Redirect):** Preserves the HTTP request method and instructs the client not to cache the redirection permanently.

## 5. PostgreSQL Core Types & Constraints

### Essential Data Types:
| Type | Purpose | Example |
| :--- | :--- | :--- |
| `SERIAL` / `BIGSERIAL` | Auto-incrementing integer managed by a database sequence | Primary keys (`1, 2, 3...`) |
| `VARCHAR(n)` | String with a fixed upper length limit | Short codes, identifiers (`VARCHAR(10)`) |
| `TEXT` | Variable-length string without arbitrary limit | Target URLs, descriptions |
| `INTEGER` | Signed 4-byte whole number | Click counters, metrics |
| `TIMESTAMPTZ` | Timestamp with timezone awareness | Creation and update timestamps |

### Key Column Constraints:
- `PRIMARY KEY`: Uniquely identifies each row in the table (implies `NOT NULL` + `UNIQUE`).
- `NOT NULL`: Rejects null/empty values for required data.
- `UNIQUE`: Rejects duplicate values across rows.
- `DEFAULT <value>`: Provides an automatic fallback value if none is supplied during insertion.
- `INDEX`: Creates a specialized lookup structure (e.g., B-Tree) for fast searching on frequently queried columns (like `short_id`).
